PRE-IMPLEMENTATION CHECKPOINT · AUGUST 29, 2026

Manual discovery is giving way to a product and coding plan.

The prototype began as a manually directed sequence of image generations and motion tests. At this checkpoint, enough of the behavior has been discovered to define a coherent interactive application rather than continue accumulating isolated experiments.

Storyboard is the workspace

Canonical locations appear left-to-right as a standard storyboard. Candidate generations stay hidden until the user opens a location to inspect or replace the Director's choice. The same storyboard supports autonomous and collaborative use.

Variable autonomy

Given a start frame, story idea, and duration, the Director can build the proposed journey itself. Users can accept it, open alternatives, or override a destination by pointing directly into a frame. Their interventions become preference signals.

Dark ride benchmark

A slow-moving original dark-ride journey is an especially useful future subject test: constrained forward motion, sequential reveals, environmental storytelling, and an obvious requirement that every location remain physically reachable along one continuous route.

Structured JSON becomes the bridge

A multimodal reasoning model should analyze semantic scene intent and emit structured data rather than arbitrary production prose. Example fields include environment, route, destination point/bounds, movement direction, slight steering, foreground occluders, atmospheric motion, confidence, and protected regions. Deterministic code consumes geometric fields for image processing; a stable prompt template consumes semantic fields for video generation.

Normalized 0–1 coordinates make the same spatial data resolution-independent across the LLM, UI, masks, motion renderer, and user interaction.

Emerging application architecture
START + STORY + DURATION→DIRECTOR / VISION LLM→SHOT JSON→RUNWAY IMAGE GENERATION→STORYBOARD→CINEMATOGRAPHER→MOTION-CONDITIONED S/E→RUNWAY VIDEO

Reasoning and media generation remain separate pathways: the LLM makes semantic/directorial decisions; Runway renders images and video. The planned SPA is TypeScript/React-oriented, with runtime schemas validating the structured contracts between those systems.

Next phase: write the UX specification, technical architecture, data model, and milestone plan; then scaffold the application against those documents. This marks the boundary between the manual genesis experiments recorded above and implementation of TunnelVision itself.

PROPOSED AUTOMATED LOOP · AUGUST 29, 2026

What we thought TunnelVision would automate at the pre-code checkpoint

This section records the August 29 proposed loop. It is not the later Camotion research checkpoint. At that moment we still treated motion-conditioned start/end frames as cinematography assets that might be paired with extra pristine references for video.

Start + story→Analyze scene→Director chooses route→Generate + evaluate→Canonical storyboard→Cinematographer shot JSON→Condition anchors + template prompt→Generate traversal

The Director and Cinematographer communicate through structured scene/shot data. The stable locomotion prompt remains mostly unchanged and is filled from semantic macros rather than freely rewritten. Geometric fields such as destination, depth, protected regions, and motion direction also drive deterministic preprocessing of motion-conditioned anchors.

Role model: TunnelVision uses real filmmaking responsibilities rather than implementation-centric agent names. The Director decides where to go; the Cinematographer decides how to get there. The final sequence order itself is effectively the edit.

Director chooses where to go; Cinematographer makes the travel believableThe Director generates and sequence-audits canonical stills for real viewpoint displacement. The Cinematographer then analyzes each accepted frame pair, infers world-appropriate occluders and motion cues, and builds a continuous-locomotion prompt based on Terran Boylan's original TunnelVision insight: movement is the governing constraint, not merely matching the destination.
